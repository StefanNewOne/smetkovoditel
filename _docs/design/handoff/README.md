# Handoff: GoDigital Finance OS — UI дизајн + системска спецификација

## Overview
Комплетен UI прототип за **GoDigital Finance OS** — интерен финансиски систем на АЛМА ДИЗАЈН ДООЕЛ Скопје (бренд GoDigital), маркетинг агенција. Системот покрива: месечни задолжувања (фактури + кеш обврски), НЛБ извод import + matching, Meta Ads префактурирање 1:1, благајна, хонорарци со билабилни алокации, извештаи и месечно затворање.

**Двата извори на вистина во овој пакет:**
1. `GoDigital_Finance_OS_MASTER_PLAN_v2.1_FINAL.md` — целосната системска спецификација (data model, парсери, workflows W1–W9, business rules B1–B18, acceptance тестови T1–T14). **Ова е примарниот документ за планот на изградба.**
2. `Finance OS.dc.html` — интерактивен UI прототип (овој документ го опишува).

## About the Design Files
`Finance OS.dc.html` е **дизајн-референца изработена во HTML** — прототип што ги покажува изгледот и однесувањето, НЕ производствен код. Задачата е овие екрани да се реизградат во target stack-от од Master Plan §11: **Next.js/Node + Prisma + PostgreSQL, Docker на VPS**, со воспоставени патерни на тој stack. Prisma шемата е веќе дефинирана во Master Plan ДЕЛ II — користи ја буквално.

## Fidelity
**High-fidelity.** Бои, типографија, растојанија, копии и интеракции се финални намери. Реизгради pixel-close со компонентна библиотека по избор (или чист Tailwind). Јазик на UI: **македонски, кирилица**. Сите износи: **МКД, integer дени** (прикажани со формат `de-DE`: 30.000).

## Screens (8 + 3 overlays)

### 1. Dashboard
4 KPI картички (салдо банка, салдо благајна, задолжено, наплатено — со под-текст извор/датум). Ред 2: панел „Задолжено vs наплатено" со 2 progress бара (Фактури=accent, Кеш=жолт) + 3 бројки под нив; панел „Топ должници" (иницијали-аватар, име, старост, износ црвено). Ред 3: „Редици за внимание" — 4 кликабилни картички (број + икона + лабела) што водат кон Import/Задолжувања. Бројачите се живи — се намалуваат кога ставка се решава.

### 2. Клиенти
Филтер чипови (Сите/Фактура/Кеш), десно „+ Нов клиент". Табела: Клиент, Канал (badge: ФАКТУРА сино / КЕШ жолто), Месечен пакет, Отворено (црвено ако >0), Дополнителни (Meta Ads · Актери), Статус. Ред-клик → профил.

**Профил:** header со аватар/име/ЕДБ/канал-badge; 4 мини-статистики (Пакет, Отворено, Маргина YTD, Преплата=creditBalance); листа задолжувања по период со статус badge. Десна колона: „Пакет-историја (верзионирано)" — timeline со точки (активна зелена), напомена B4: промена = нова верзија, edit не постои; „Дополнителни ставки" со billing mode (PASSTHROUGH_ACTUAL).

**Wizard „Нов клиент" (модал, 5 чекори,** progress од сегменти во accent**):**
1. Основни податоци (име, email)
2. Канал на наплата — 2 картички (📄 Фактура: +18% ДДВ, бара ЕДБ / 💵 Кеш: без ДДВ, интерна обврска); избор Фактура открива задолжително ЕДБ поле (B17)
3. Месечен пакет — внес на основица + **live ДДВ preview** (Основица / ДДВ 18% / Вкупно; за кеш ДДВ=„0 (кеш)")
4. Дополнителни ставки (Meta Ads AdAccount мапирање, Актери D2 — автоматски)
5. Потврда: „Од 01.08 влегува во W1"

### 3. Задолжувања
Месец-селектор + инфо „W1 извршен 01.07 06:00". Копчиња „Книжно одобрение" и „Одобри ги сите DRAFT". Табела: Клиент, Број, Вид (ФАКТУРА/КЕШ ОБВ.), Основица, ДДВ 18% (— за кеш), Вкупно, Статус + акции. **Клучна интеракција:** „Одобри" на DRAFT → добива следен слободен број `1-{n}/7-2026` (B1: без дупки, при издавање) и станува OPEN; потоа бројот е кликабилен → PDF преглед. Футер напомена за B1/B12.

### 4. Import центар
Лева колона „НЛБ изводи": multi-upload зона + листа на изводи со header податоци (претходно/долгува/побарува/ново/налози) и **интегритет линија** (зелена ✓ салдо+бр.налози+континуитет, или сива „B13: дупликат тивко скокнат"). Десна: 4 таба-редици со живи бројачи — Извод-линии / Receipts без линија / FACEBK без receipt / PARTIAL parse. Секоја ставка: икона, наслов, износ, контекст, акции („Класифицирај"/„Потврди предлог"/„Спари со Charge" — ја решаваат ставката; „Прегледај PDF"). Празна редица → „✓ Редицата е празна".

### 5. Благајна
3 KPI (салдо + „B3: никогаш негативна", влез, излез). Благајнички дневник: датум, опис, документ (ФИСКАЛНА бр. X (D6) / КАСА-ИСПЛАТИ бр. X), counterparty тип, износ (+зелено/−црвено), 📎 индикатор за слика (задолжителна за исплати, B5). Копчиња „Попис" и „+ Кеш-трошок (мобилен)".

### 6. Хонорарци
Лева: регистар (аватар, име + 🎬 за isTalent, тип договор + taxMode, rate); селекција со bg `#eef4fd`. Десна: **пресметка (пример T13 — Вања С.)**: Бруто 30.000 / Данок 10% 3.000 / Нето 27.000; табела алокации по клиент (Астибо 18.000/60% billable ДА → „ACTORS ставка на фактура"; Интерно 12.000/40% НЕ → „само маргина"); копче „Исплати од благајна" → потврда: атомски CashLedgerEntry + авто Expense(ACTORS) 18.000 isBillable + напомена B16.

### 7. Извештаи
Маргина по клиент (хоризонтални барови, боја по праг: ≥30% зелено, 10–30% жолто, <10% црвено); Aging (4 buckets 0-15/16-30/31-60/60+); темна картичка „Пакет за сметководител (W9)" со Преземи ZIP; ред P&L картички (Приходи/Трошоци/Добивка YTD, Cash flow).

### 8. Подесувања
Grid 3 колони картички: ДДВ (B11), Банка и салда, Ad акаунти, Vendor правила, RBAC, Нумерација („следен: 1-6/7-2026").

### Overlay A — Фактурен PDF темплејт (§7, D1)
Модал 620px, бел „лист": лого + „АЛМА ДИЗАЈН ДООЕЛ Скопје / Даночен број: 4032023558371 / Жиро сметка: 210-0768360001-38 / НЛБ Банка АД Скопје"; десно „ФАКТУРА" + број + датуми (издавање/валута-рок); box „Примач" со ЕДБ; табела линии (Опис+под-опис со sourceRefs следливост, Основица, ДДВ 18%, Износ) со дебела долна граница на header; сума блок (Основица/ДДВ/ВКУПНО ден); футер: „При плаќање наведете повикување на број: {број}" + линија за потпис. Кирилична типографија задолжителна во PDF генерирањето.

### Overlay B — Мобилен PWA внес (W6)
Телефонска рамка 375px. Тек: (1) камера зона — dashed сина, „Фотографирај сметка · задолжително за кеш-трошок (B5)"; (2) по слика → зелена потврда + **OCR prefill** банер, износ и опис пополнети; (3) категорија чипови; (4) „Зачувај трошок" — **блокирано без слика**: копчето сиво, обид за клик → камера зоната станува црвена + порака „⛔ B5: кеш-трошок без слика е блокиран"; со слика → „✓ Зачувано атомски" (Expense + CashLedgerEntry + слика — една трансакција).

### Overlay C — Toast
Темен pill (`#1a2333`), bottom-center, auto-hide 3.8s — за системски пораки/потврди.

## Interactions & State (резиме)
- Navigation state: активен екран, селектиран клиент (list↔profile)
- Charges: approve DRAFT→OPEN со доделување број; approve-all; PDF модал по charge
- Import: решавање ставка → отстранување од редица + декремент на бројачи (таб, dashboard картичка, sidebar badge) + toast потврда
- Wizard: чекор-состојба, канал-избор влијае на ДДВ preview и ЕДБ поле; live пресметка при внес
- Mobile: hasPhoto gate за save (B5), saveTried error state
- Contractor pay: еднонасочен премин CALCULATED→PAID со потврда за авто-ставки
- Сите „идни" акции (Попис, Multi-upload, Книжно одобрение, ZIP, подесувања) во прототипот даваат објаснувачки toast со референца на правилото — во продукција тоа се вистински екрани/текови по Master Plan.
